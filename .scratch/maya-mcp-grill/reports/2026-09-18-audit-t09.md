## 三、缺陷清单（打回项）

### F-1（实质）phantom validator 扩展机制 —— 文档宣称了代码不存在的 API
- **证据**：README.md:24 与 README_en.md:24 把"自注册 validator 扩展机制"列入**本项目独有**档；skills/scene-review-playbook/SKILL.md:44-46 "Custom validators" 节记载 `register(name, fn, severity, family)` API 与 `check_error` 语义。
- **实物**：src/ 全树无 register/check_error/注册表（grep 仅命中 register_scene_tools MCP 注册与英文单词 register）；scene_review 检查为硬编码 `if "x" in checks` 块（maya_scene_module.py:2773-3273）；check_error 在 src/tests 零命中。
- **根源**：D-011/ADR-0008 决策了该注册表但**从未实现**（git log -S 仅命中文档提交）。且 D-011 原文："文档口径=受信 agent 扩展机制（逃生舱），**非发布卖点**"——即便实现了也不能进独有卖点档。D-030 spec 文本虽在独有档列举了"注册表"，但同 spec 的 DoD 要求"README 每个数字可对源"、"全部数字以代码为真源"——实现者应识别 spec 与代码的冲突并如实处理，而非照抄。
- **讽刺点**：rui.txt P2 批评的正是同类幻影（"4 个 Codex Skills"、不存在的 get_output 工具）——T-09 的任务就是消灭幻影，却新增了一条。
- **修复要求**：README.md:24/README_en.md:24 删除或改写该档条目（可用的真实替代：scene_validate 自定义约束规则 check_constraints 已实装）；SKILL.md "Custom validators" 整节删除或改写为真实扩展路径（write_module + check_constraints），并保证卡内不出现未实现 API 签名。
