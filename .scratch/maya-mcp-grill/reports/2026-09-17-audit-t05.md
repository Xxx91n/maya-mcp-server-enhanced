## §3 必修项

### F-1 D-013 headless 回退为死代码 + headless 僵尸会话（spec 失败）

D-013 原文："native 降级为 bootstrap/发现+headless(mayapy无Qt事件循环) 最小通道并文档化"。现实现两层独立失效：

- **A 层（启动失败路径不可达）**：helper.start_qt_server（maya_mcp_helper.py:561-574）自捕获异常返回 {"error":…} JSON 串 → native _send_receive（client.py:463-469）见 "error" 键且 raise_on_error 默认 True → 直接抛 MayaExecutionError → bootstrap() :594-598 的 qt_error 检查永远拿不到错误 → :598-614 的 START_COMMAND_PORT 回退分支不可达。
- **B 层（headless 下 Qt 启动根本不失败）**：mayapy 自带 PySide6；QTcpServer.listen() 在无 QCoreApplication 事件循环时仍可成功（listen 为同步 socket 调用），但 newConnection/readyRead 信号永不派发 → bootstrap("qt") 返回真实端口 → TCP connect 走内核 backlog 成功 → 会话登记为 framed → 一切请求 readexactly 超时 → MayaTimeoutError 僵尸会话，随后被 _failed_ports dedup。helper 与 client 中无任何 QCoreApplication/about(batch) 事件循环检测（grep=0）。
- **掩盖**：test_qt_start_failure_falls_back_to_native（test_client.py:677+）mock _send_receive 返回 CommandResponse(error={...})——真线永不产生该形状（真线要么 raise，要么把错误 JSON 串放在 result 里）。测试绿 ≠ 功能活。

修复方向（返工窗口自定实现）：
1. Maya 侧自证：start_qt_server 前先探事件循环（QCoreApplication.instance() 或 cmds.about(batch=True)），无则返回显式 {"error":{"code":"qt_unavailable_headless",...}}（D-019 域错形状）。
2. 客户端契约：START_QT_SERVER 调用改为 raise_on_error=False，或按 result 为 JSON 串的真线形状解析后判 error——使回退分支真实可达。
3. 回归测试按真线形状重写：至少两钉——(a) start_qt_server 返回/抛出错误→落到 MayaClient native 会话；(b) 无事件循环（模拟 QCoreApplication.instance()=None 或 batch）→native 会话。断言 _send_receive 收到的 raise_on_error 形状与真实实现一致。
